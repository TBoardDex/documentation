# TBoard Documentation

Official documentation site for TBoard open-source hardware and software,
built with Docusaurus 2.4.3.

## Domains

| Site | URL |
| --- | --- |
| Documentation (overseas, EN) | https://docs.tboard.org |
| Documentation (China, ZH) | https://docs.tboard.cn |
| Website (overseas) | https://www.tboard.org |
| Website (China) | https://www.tboard.cn |
| Forum | https://forum.tboard.org |

The five domains are defined as constants at the top of `docusaurus.config.js`.
`url` only affects canonical tags and sitemap; the actual deployment target is
decided by the GitHub Actions workflow and its Secrets.

## Local development

```bash
npm ci
npm run start                  # English, http://localhost:3000
npm run start -- --locale zh   # Chinese, http://localhost:3000/zh/
npm run build                  # produces build/ and build/zh/
npm run serve                  # preview the production build
```

## Documentation structure

```
docs/main/
  main-page.md              landing page (slug: /) — Hero + path cards + showcase
  quick-start/              Quick Start / 快速上手           (position 1)
    r5a-rk3588s/            R5A (RK3588S) / R5A（RK3588S）   (6 pages)
  boards/                   Boards / 开发板                 (position 2, per-board: overview + pinout)
    r5a/                    R5A (RK3588S) / R5A（RK3588S）   (overview.md + pinout.md)
  downloads/                Downloads / 资料下载             (position 3, 5 pages)
  common/                   Common / 通用                   (position 4, platform-common only:
                                                              overview + GPIO, UART, I2C, SPI, PWM,
                                                              USB, Display, Camera, Audio — no
                                                              board-specific pinouts here)
  system-sdk/               Accessories / 外围配件          (position 5, overview only)
  linux/                    Linux / Linux                   (position 6, 1 page)
  android/                  Android / Android               (position 7, 1 page)
  others/                   Others / 其他                   (position 8, overview only)
  licenses/                 Licenses / 许可协议              (position 9, 2 pages, last)
i18n/zh/docusaurus-plugin-content-docs/current/main/   Chinese mirror, strict 1:1
```

Category labels and order live in each `_category_.json` (one EN + one ZH).
The sidebar is autogenerated by `sidebars.js`, so adding a `.md` file is enough —
but the matching Chinese file must be added at the same time.

Docusaurus 2.4.3 builds the sidebar from the English `_category_.json` only, so
Chinese labels come from `src/sidebarLabels.json`, applied by
`sidebarItemsGenerator` in `docusaurus.config.js`. After renaming a category or
a page, run `../gen-sidebar-labels.py` to regenerate that map.

### Board naming convention

Quick Start is grouped **by board**, and each group label carries the SoC model
so multiple chip platforms stay easy to locate: `R5A (RK3588S)` /
`R5A（RK3588S）`. To add a board, create `quick-start/<board>-<soc>/`
(lower case, e.g. `quick-start/r5b-rk3576/`), copy the six onboarding pages,
and set its `_category_.json` label to `R5B (RK3576)` / `R5B（RK3576）`.
Keep the same order in both locales. Downloads keeps a matching per-board
index table in its overview page. Quick Start stays short: board introduction,
assembly, firmware download, flashing, first boot and a basic compile only —
anything deeper belongs in Boards, Downloads, Accessories or Others.

Stable slugs used by the homepage, footer and quick-jump menu:

| Page | Slug |
| --- | --- |
| R5A quick start / assembly / firmware download | `/quick-start` `/assembly` `/download-firmware` |
| Flashing / first boot / basic compile | `/flashing` `/first-boot` `/basic-compile` |
| Downloads hub | `/downloads` `/hardware-files` `/firmware-images` `/sdk-sources` `/tools` |
| Accessories hub | `/accessories` |
| R5A product page / pinout | `/tboard-r5a` `/r5a-pinout` |
| Software / hardware licences | `/licenses/software` `/licenses/hardware` |
| Common / Linux / Android / Others | `/common` `/gpio` `/linux` `/android` `/others` |

Accessories and Others are intentionally single-page sections: each keeps only
its own `/accessories` or `/others` overview, and device / system pages are
added one by one once they are verified on hardware.

## Visual layer

`src/css/custom.css` implements the TBoard brand theme — navy `#043266`,
deep navy `#032652` and circuit cyan `#1ab2c6`, sampled from the wordmark —
with a light and a dark variant.

| File | Purpose |
| --- | --- |
| `src/components/siteData.js` | EN/ZH copy, card data, quick-jump groups, navbar icon paths |
| `src/components/HomeHero.js` | Landing hero, CTAs, metrics and hero image |
| `src/components/PathCards.js` | Nine section cards (one per top-level group) |
| `src/components/HomeShowcase.js` | Firmware-chain showcase, community block, draft notice |
| `src/components/QuickNav.js` | Navbar quick-jump mega menu (desktop + mobile) |
| `src/components/IconLink.js` | Navbar hyperlink with a stroked icon badge (EN/ZH label) |
| `src/sidebarLabels.json` | EN → ZH sidebar label map (Docusaurus 2.4.3 reads `_category_.json` from the English docs only) |
| `src/theme/SearchBar/index.js` | Top-right local search button + command palette |
| `plugins/tboard-search.js` | Build-time EN/ZH search index from the markdown sources |
| `src/theme/NavbarItem/ComponentTypes.js` | Registers `custom-quicknav` and `custom-iconlink` |

`docusaurus.config.js` wires the logo (`img/tboard-logo.png`), the dark-theme
variant (`img/tboard-logo-dark.png`), the favicon, the social card
(`img/og-cover.png`), the icon hyperlinks (`custom-iconlink` items with `icon`,
`label`, `labelZh`) and the quick-jump menu. To add a shortcut, edit
`QUICK_GROUPS` in `siteData.js` — both languages are defined side by side.

### Navigation rails and search

Both doc rails stay on **every** page: the autogenerated sidebar on the left and
the table of contents on the right. The landing page keeps them too — its hero,
cards and showcase adapt to the narrower centre column through
`body:has(.tb-hero)` rules in `custom.css` instead of hiding the rails.

The search button sits in Docusaurus' native top-right `NavbarSearch` slot.
The classic theme ships a no-op `SearchBar`; `src/theme/SearchBar/index.js`
replaces it with a local search over `plugins/tboard-search.js` global data.
No Algolia account, no npm dependency and no workflow change. Shortcuts:
`Ctrl/Cmd+K` or `/` to open, `↑`/`↓` + `Enter` to navigate, `Esc` to close.
The index is regenerated from `docs/main/` and the Chinese mirror on every
`npm run start` / `npm run build`, so newly added pages are searchable
automatically.

## Image placeholders

All content pages contain a branded placeholder whose pixel dimensions are
printed on the image itself, plus a caption with the same dimensions. Replace
the file with a real image of the same size and update the caption.

| File | Size | Suggested use |
| --- | --- | --- |
| `static/img/placeholder-1200x675.png` | 1200 × 675 | board photo / hero banner |
| `static/img/placeholder-960x540.png` | 960 × 540 | build or boot flow diagram |
| `static/img/placeholder-800x450.png` | 800 × 450 | procedure screenshot |
| `static/img/placeholder-640x360.png` | 640 × 360 | compact diagram |
| `static/img/placeholder-600x400.png` | 600 × 400 | connector or pinout drawing |
| `static/img/placeholder-400x300.png` | 400 × 300 | small icon or photo |
| `static/img/og-cover.png` | 1200 × 630 | social share card |

Reference images as `/img/name.png`. The legacy `placeholder.svg` is kept for
compatibility. Placeholder artwork is generated locally by
`../enhance-tboard-assets.py`; category renaming, slugs and image injection are
generated by `../enhance-tboard-structure.py`, and the current v3 tree (per-board
Quick Start, Downloads, Others, Licenses last) by `../update-sidebar-v3.py`.
The Accessories rename, the Common ordering and the `/accessories` overview page
are applied on top by `../update-accessories-v4.py`.
The `system-sdk/` folder name is kept so the stable `/accessories` route and the
folder layout do not change; only its sidebar label is Accessories / 外围配件.
`../retire-section-pages-v5.py` then reduces Accessories and Others to their
overview page, archiving the 38 retired markdown files (19 EN + 19 ZH) under
`../_v3-retired/{en,zh}/system-sdk|others/`. Nothing is hard-deleted.
The v3 script moves superseded directories to `../_v3-retired/` instead of
deleting them.

## Writing rules

- Use only TBoard-owned domains and download endpoints.
- Keep the Chinese mirror 1:1 with the English docs.
- MDX treats `<Something>` as a JSX tag. Wrap such placeholders in backticks.
- Keep board-specific facts (pinouts, download links, revision data) on the
  TBoard R5A product page; other pages link to it instead of duplicating data.
- Rich visual blocks belong in `src/components/*.js`; keep `.md` files mostly
  Markdown so the MDX audit stays quiet.
- Run `node ../verify-rebuilt-docs.mjs` and `npm run build` before merging.

## Deployment

`.github/workflows/deploy-docs.yml` is the deployment contract. The owner edits
it directly on GitHub (comments and Secrets), so keep the build and deploy logic
itself unchanged — comment / whitespace edits are fine. A push to `main`
triggers:

```
npm ci -> npm run build
  build/     -- rsync -avz --delete --> EN server (docs.tboard.org)
  build/zh/  -- rsync -avz --delete --> CN server (docs.tboard.cn)
```

Eight repository secrets are required: `WEB_PATH`, `SSH_HOST`, `SSH_USER`,
`SSH_PRIVATE_KEY`, `CN_WEB_PATH`, `CN_SSH_HOST`, `CN_SSH_USER`,
`CN_SSH_PRIVATE_KEY`. These belong in **repository** secrets, not environment
secrets, because the deploy jobs declare no `environment:`.

Because the workflow uses `rsync --delete`, an empty or half-finished site on
`main` would wipe the live servers. Do day-to-day writing on the `develop`
branch, verify locally, and merge to `main` only when the content is ready.

Chinese pages generate `/zh/`-prefixed internal links. If the CN server serves
`build/zh/` at the site root, configure a rewrite from `/zh/` to `/`, or mount
the Chinese build under `/zh/`.
