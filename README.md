# TBoard Documentation

Official documentation site for TBoard open-source hardware and software,
built with Docusaurus 2.

## Domains

| Site | URL |
| --- | --- |
| Documentation (overseas, EN) | https://docs.tboard.org |
| Documentation (China, ZH) | https://docs.tboard.cn |
| Website (overseas) | https://www.tboard.org |
| Website (China) | https://www.tboard.cn |
| Forum | https://forum.tboard.org |

The five domains are defined as constants at the top of `docusaurus.config.js`.
Edit them there and commit. `url` only affects canonical tags and sitemap;
the actual deployment target is decided by the GitHub Actions workflow and its
Secrets.

## Local development

```bash
npm ci
npm run start            # English
npm run start -- --locale zh
npm run build            # produces build/ and build/zh/
```

## Structure

```
docs/main/
  main-page.md           landing page (slug: /)
  FAQ.md
  TBoard Product/        product pages (currently TBoard R5A)
  Getting Started/       downloads, flashing, first boot, system setup
  Interface Usage/       peripherals and interfaces
  Advanced Manual/       SDK, device tree, boot flow, NPU
  build_and_deploy/      firmware build chain to update.img
  Open Source/           software and hardware licences
i18n/zh/                 Chinese mirror, strict 1:1 with docs/main
static/img/              self-authored images
```

The sidebar is autogenerated from `docs/main/`. Adding a `.md` file is
enough; `sidebars.js` does not need to be edited. Keep the Chinese mirror in
sync by adding the matching file under
`i18n/zh/docusaurus-plugin-content-docs/current/main/`.

Most pages are DRAFT placeholders with a writing brief. Fill them in
progressively.

## Writing rules

- Use only TBoard-owned domains and download endpoints.
- Images go into `static/img/` and are referenced as `/img/name.svg`.
  `/img/placeholder.svg` is a reusable 16:9 placeholder.
- MDX treats `<Something>` as a JSX tag. Wrap such placeholders in backticks.
- Keep board-specific facts (pinouts, download links, revision data) on the
  TBoard R5A product page; other pages link to it instead of duplicating data.

## Deployment

`.github/workflows/deploy-docs.yml` is the deployment contract and must not be
modified. A push to `main` triggers:

```
npm ci -> npm run build
  build/     -- rsync -avz --delete --> EN server (docs.tboard.org)
  build/zh/  -- rsync -avz --delete --> CN server (docs.tboard.cn)
```

Eight Actions secrets are required: `WEB_PATH`, `SSH_HOST`, `SSH_USER`,
`SSH_PRIVATE_KEY`, `CN_WEB_PATH`, `CN_SSH_HOST`, `CN_SSH_USER`,
`CN_SSH_PRIVATE_KEY`. Without them the build job fails but nothing is synced.

Because the workflow uses `rsync --delete`, an empty or half-finished site on
`main` would wipe the live servers. Do day-to-day writing on the `develop`
branch, verify `npm run build` locally, and merge to `main` only when the
content is ready.

English and Chinese locales must both be kept: `deploy-cn` depends on the
`build/zh/` output.
